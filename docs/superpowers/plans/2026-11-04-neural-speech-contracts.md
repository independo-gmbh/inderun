# Neural Speech Contracts (PR 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the contract foundation for on-device neural TTS: speech model packages, multilingual voices the planner can match, a provider-measured first-chunk timing, and a voice catalog that tells platform voices from model voices.

**Architecture:** Every change is additive JSON Schema under `contracts/schemas/`, regenerated into TS/Swift/Kotlin/Rust by `pnpm generate`, pinned by shared fixtures under `contracts/fixtures/` that all SDK suites load. The shared Rust planner learns to match a voice's `locales`; the three hand-written speech facades pass the new fields through and derive `kind` from the capability snapshot. No provider, host service or runtime code is touched.

**Tech Stack:** JSON Schema 2020-12 + quicktype (`contracts/scripts/generate-contracts.mjs`), Ajv (`packages/contracts`), Rust route core (`rust/inderun-route-core`, FFI/JNI/WASM), Swift 5.9 SwiftPM, Kotlin/Gradle, Vitest/XCTest/JUnit.

**Spec:** `docs/superpowers/specs/2026-11-04-neural-speech-design.md` (section A, "Contracts")

## Global Constraints

- Additive schema changes only: no `schemaVersion` bump, no `$id` version segment change (`contracts/README.md` "Schema evolution").
- `ProviderVoice.locale` stays required; `locales` is optional and additional.
- `speech.pipeline` is an open string, never an enum (no codegen churn per model family).
- No "neural" marker on the wire: `kind` lives only in the facades' `SpeechVoiceInfo`, derived from `descriptor.model`.
- Generated files are never hand-edited: `packages/contracts/src/generated/`, `ios/IndeRun/Sources/IndeRunContracts/Contracts.swift`, `android/inderun-contracts/.../Contracts.kt`, `rust/inderun-route-core/src/generated/contracts.rs`.
- A route-core change requires `pnpm build:route-core-apple` and committing `ios/IndeRun/Frameworks/InderunRouteCoreFFI.xcframework` plus `InderunRouteCoreFFI.provenance.json` in the same commit (CLAUDE.md §6).
- Branch `feat/m5-neural-speech-foundation`, PR into `dev`, Conventional Commits, trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` last (above any `BREAKING CHANGE:` footer).
- Prettier covers `ts/mjs/js` only; fixtures and schemas are formatted by hand to match their neighbours (2-space JSON).

## Review Focus

1. A request locale must match any entry of `locales` by language and case-insensitively (`en-GB` finds a voice listing `en-US`; `EN-us` exact finds `en-US`) — pinned by fixture cases `locale_filter_matches_any_listed_locale` and `exact_locale_filter_uses_listed_locales` (Task 4) and planner case `multilingual_voice_binds_listed_language` (Task 2). Underscore-region tags (`de_AT`) match by language only; the exact-region comparison compares whole tags and does not normalise `_` (pre-existing behaviour, unchanged).
2. A voice whose `locales` omit its own `locale` must still match that `locale` — `voice_locales()` yields `locale` first; planner case `multilingual_voice_exact_region_via_locales` has a voice without `locales` (Task 2).
3. A `text_to_speech` package with two voices sharing an id must be refused before any provider loads it — `rejects duplicate speech voice ids` on all three platforms (Task 1).
4. A `coreai` package handed to today's ONNX text providers must be refused with the existing "unsupported model format" reason, not crash — one test per platform (Task 1).
5. An available provider whose `text_to_speech` task reports `available: false` must still be skipped by `listVoices()` after the `kind` change — fixture case `platform_and_model_voices` carries such a snapshot (Task 4).

- [ ] **Step 1: Write the ADR** (template from the README; Status: Accepted)

Context: issue #260, the product need (neural voices as options, system voices as fallback, user-selected voice), the three runtime constraints from the spec ("Decisions" 3–7a), and the gaps found in code (text-only `ModelPackage`, single-tag `ProviderVoice.locale`, no first-chunk timing). Decision: (1) one `ModelPackage` describes any local model: `format` adds `coreai`, `variant` separates bytes from identity, `speech` carries pipeline, graphs, frontend and voices, and `pipeline` is an open string; (2) `ProviderVoice.locales`; (3) `PlaybackOutput.firstChunkMs`; (4) `kind` is a facade derivation, never a wire field. Consequences: one neural speech provider per runtime instead of one per model family (spec section C), Core AI reuses the same package (spec section D), the planner binds multilingual voices, benchmarks can separate synthesis from output latency; constrained: no "neural" claim on the wire, no download semantics in the package (ADR 019 §5 unchanged).
